# دليل شرح ملفات مشروع Loulou AI

هذا الملف يشرح وظيفة كل ملف في المشروع، وكيف تعمل الملفات معًا، وأين تعدّل عند ربط الخدمة مع فريق Laravel.

## 1. فكرة المشروع باختصار

المشروع خدمة Python مستقلة مبنية باستخدام FastAPI. تستقبل رسالة العميل من Laravel، تفهم المطلوب، وتجلب بيانات المنتجات أو المتاجر أو الأسئلة الشائعة أو الطلبات، ثم ترجع ردًا منظمًا تستطيع الواجهة عرضه.

المساعد يدعم العربية والإنجليزية، ويستخدم كلام العميل داخل الجلسة للترشيح عبر المتاجر. تتبع الطلب يحتاج رقمًا يكتبه العميل، وهوية عميل موثوقة من Laravel، والتحقق من ملكية الطلب. لا توجد عمليات شراء أو دفع أو إلغاء.

**دور OpenAI في الكود الحالي:** يحدد نية العميل ويستخرج تفاصيل مثل المنتج والميزانية ورقم الطلب في نتيجة منظمة. بعد ذلك يجلب كود Python البيانات ويكوّن الرد باستخدام قوالب عربية وإنجليزية وبيانات الـbackend. النموذج لا يكتب الرد النهائي بحرية، ولا توجد مكالمة ثانية له لإعادة صياغة نتائج البحث.

### أوضاع التجربة والربط

| الإعداد | ماذا يفعل؟ |
|---|---|
| `PLANNER_MODE=demo` | يفهم بعض الطلبات بقواعد وكلمات مفتاحية محلية، دون الاتصال بـOpenAI. |
| `PLANNER_MODE=openai` | يستخدم OpenAI لفهم الرسالة واستخراج القرار المنظم. |
| `BACKEND_MODE=mock` | يقرأ بيانات تجريبية من `app/data/catalog.json`. |
| `BACKEND_MODE=laravel` | يقرأ البيانات من endpoints فريق Laravel. |

يمكن تشغيل OpenAI مع البيانات التجريبية قبل اكتمال الـbackend.

## 2. رحلة رسالة العميل

```text
العميل يكتب في الواجهة
          ↓
Laravel يرسل الرسالة وهوية الجلسة الموثوقة
          ↓
main.py يتحقق من الطلب والصلاحيات وحدود الاستخدام
          ↓
sessions.py يفتح جلسة تخص هذا العميل
          ↓
service.py يدير المحادثة
          ↓
planner.py يفهم المطلوب باستخدام OpenAI أو قواعد التجربة
          ↓
gateway.py يجلب البيانات من Laravel أو ملف التجربة عند الحاجة
          ↓
service.py يتحقق من النتائج ويكوّن الرد بمساعدة replies.py
          ↓
Laravel يستقبل JSON ويرسله للواجهة
```

تُستخدم `models.py` للتحقق من شكل البيانات، و`config.py` للإعدادات، و`text.py` لمعالجة النصوص أثناء هذه الخطوات. التحية مثلًا لا تحتاج جلب بيانات من الـbackend.

## 3. ملفات التطبيق: مجلد app

### `app/main.py` — مدخل الخدمة واستقبال الطلبات

هذا الملف يبدأ تطبيق FastAPI ويربط المكونات ببعضها من خلال `create_app()`.

- يختار مكوّن فهم الرسائل ومصدر البيانات ومكان حفظ الجلسات حسب الإعدادات.
- يتحقق من مفتاح الخدمة ومن بيانات الهوية التي يرسلها Laravel في الـheaders.
- يضع حدودًا لحجم الطلب، وعدد الطلبات، والطلبات التي تعمل في نفس الوقت.
- يحوّل الأخطاء إلى ردود API واضحة، ويضيف رقمًا لتتبع الطلب.
- يبدأ تنظيف الجلسات المنتهية، ويغلق الاتصالات عند إيقاف التطبيق.

المسارات التي يوفّرها:

| المسار | الوظيفة |
|---|---|
| `POST /v1/chat` | استقبال رسالة وإرجاع رد المساعد. |
| `DELETE /v1/sessions/{session_id}` | حذف جلسة يملكها العميل عند إنهاء المحادثة. |
| `GET /health/live` | التأكد أن عملية الخدمة تعمل. |
| `GET /health/ready` | فحص مخزن الجلسات وإظهار أوضاع التشغيل؛ لا يفحص اتصال OpenAI أو Laravel. |

**تعدّله عندما:** تحتاج endpoint جديدًا، أو تغيير طريقة استقبال الطلبات والتحقق منها. الواجهة تتعامل مع Laravel، وLaravel يتعامل مع هذه الخدمة بمفتاح داخلي.

### `app/config.py` — قراءة الإعدادات والتحقق منها

يحتوي على `Settings`، ويقرأ القيم من متغيرات البيئة وملف `.env`.

الإعدادات تشمل مفاتيح الخدمات، اسم نموذج OpenAI، عناوين Laravel، المهلات الزمنية، عدد الترشيحات، مدة الجلسة، Redis، ورقم واتساب.

يتحقق من صحة الإعدادات قبل التشغيل؛ مثل وجود مفتاح ونموذج عند تشغيل OpenAI، وصحة مسارات Laravel، ومتطلبات وضع الإنتاج مثل Redis وHTTPS.

**تعدّله عندما:** تضيف إعدادًا جديدًا أو قاعدة تحقق جديدة. تغيير قيمة إعداد موجود يكون عادة في `.env`.

### `app/models.py` — تعريف شكل البيانات

يستخدم Pydantic لتعريف الحقول المقبولة وأنواعها والتحقق منها. مثلًا: رسالة العميل من 1 إلى 300 حرف، الأسعار أرقام مناسبة، والتواريخ المطلوبة تشمل المنطقة الزمنية.

أهم النماذج:

| النموذج | يمثل ماذا؟ |
|---|---|
| `ChatRequest` | الرسالة القادمة، ورقم الجلسة الاختياري، واللغة، وسياق المتجر. |
| `Principal` | هوية صاحب الجلسة وهوية العميل المسجل إن وجدت. |
| `Decision` | قرار فهم الرسالة: نوع الطلب، كلمات البحث، الميزانية، رقم الطلب، وسؤال المتابعة. |
| `Search` | معايير البحث عن المنتجات. |
| `Store`, `Product`, `FAQ`, `Order` | البيانات المتوقعة من مصدر البيانات. |
| `ProductCard`, `StoreCard`, `OrderCard` | البيانات المجهزة للعرض في الواجهة. |
| `Handoff` | معلومات التحويل للدعم. |
| `ChatResponse` | الرد الكامل الذي تعيده الخدمة. |
| `Session` | لغة الجلسة، وتاريخ المحادثة، والمالك، وموعد الانتهاء. |

**تعدّله عندما:** تتفق مع فريق Laravel أو الواجهة على إضافة حقل أو تغيير شكل بيانات الـAPI. تغيير هذه النماذج قد يستلزم تعديل باقي الملفات وتحديث التوثيق.

### `app/planner.py` — فهم رسالة العميل

يحتوي على طريقتين لتنفيذ نفس المهمة:

- **`OpenAIPlanner`:** يرسل الرسالة وسياق المحادثة إلى Responses API، ويطلب استدعاء دالة منظمة اسمها `route_customer_message`. يتحقق من النتيجة ويحوّلها إلى `Decision`.
- **`DemoPlanner`:** يستخدم كلمات وقواعد محلية لتجربة التطبيق بدون مفتاح OpenAI. قدرته على الفهم محدودة، ولا يمثل جودة النموذج الحقيقي.

المتغير `INSTRUCTIONS` يحتوي على تعليمات النموذج: فهم احتياج العميل، استخدام سياق الجلسة، عدم اختراع رقم طلب، وعدم تنفيذ عمليات دفع أو إلغاء.

الكلاس `Planned` يجمع القرار مع عدد tokens المستخدمة. الاتصال يستخدم `store=False` ولا يرسل كائن هوية العميل إلى النموذج، لكن نص الرسائل نفسه قد يحتوي معلومات كتبها العميل.

**تعدّله عندما:** تريد تحسين فهم النية، أو استخراج الميزانية، أو قواعد طلب التوضيح. نصوص الرد النهائي موجودة في `replies.py`.

### `app/gateway.py` — الوصول إلى بيانات المتاجر والطلبات

يعزل التعامل مع مصدر البيانات عن منطق المحادثة.

- **`BackendGateway`:** يحدد العمليات التي يحتاجها التطبيق: المنتجات، المتاجر، الأسئلة الشائعة، وتتبع الطلب.
- **`MockGateway`:** ينفذها باستخدام ملف البيانات التجريبية، مع بحث بسيط وفلترة للميزانية والتوفر.
- **`LaravelGateway`:** ينفذها بطلبات HTTP من نوع `GET` إلى Laravel باستخدام المفتاح الداخلي والمهلة المحددة.
- **`safe_url()`:** يتحقق من أن الروابط تستخدم HTTPS وأن نطاقها ضمن القائمة المسموح بها.

يتوقع الربط الحالي أن تحتوي استجابة Laravel على مفتاح `data`، ثم يتحقق من الحقول باستخدام نماذج `models.py`. البحث يشمل كل المتاجر. عند تتبع الطلب يرسل هوية العميل ويتحقق أيضًا من رقم الطلب ومالكه في النتيجة.

**تعدّله عندما:** تختلف أسماء الحقول أو بنية JSON التي سيرسلها Laravel عن العقد الحالي. إذا كانت البنية متطابقة وتغيّر العنوان أو المسار فقط، يكفي ضبط `.env`.

### `app/service.py` — إدارة المحادثة وتنفيذ القرار

يحتوي على `ChatService`، وهو الجزء الذي يجمع فهم الرسالة والبيانات والرد النهائي.

الدالة `respond()` تدير الرسالة كاملة: تحديد اللغة، فهم الطلب، تنفيذ القرار، التعامل مع التأخير أو الفشل، وتحديث تاريخ الجلسة. الدالة `_execute()` تنفذ نوع العملية المطلوب.

مسؤولياته الأساسية:

- ترشيح منتجات مناسبة، والتحقق من السعر والتوفر ونشاط المتجر والروابط، وإزالة النتائج المكررة.
- تجهيز بطاقات المنتجات والمتاجر للواجهة.
- عرض إجابات الأسئلة الشائعة القادمة من مصدر البيانات.
- طلب توضيح قصير عندما تكون تفاصيل الترشيح ناقصة.
- طلب رقم الطلب قبل جلب بياناته، ثم اشتراط تسجيل الدخول والتحقق من الملكية.
- التأكد أن رقم الطلب الذي اختاره النموذج موجود في رسالة العميل الحالية.
- تقديم رد مناسب عند انقطاع إحدى الخدمات أو تجاوز المهلة.
- حفظ عدد محدود من رسائل الجلسة، وحجب تفاصيل رد تتبع الطلب من سياق المساعد الذي سيُرسل لاحقًا للنموذج.

**تعدّله عندما:** تريد تغيير خطوات المحادثة أو قواعد الترشيح أو التعامل مع نتائج الـbackend. مثال: تغيير ما يحدث عند عدم وجود منتج مناسب.

### `app/replies.py` — نصوص الردود بالعربي والإنجليزي

يجمع القوالب التي يستخدمها المساعد: التحية، طلب الميزانية، طلب رقم الطلب، رسائل الانتظار والفشل، حدود قدرات المساعد، والتحويل للدعم.

- `TEXT`: نصوص الردود باللغتين.
- `STATUSES`: ترجمة حالات الطلب.
- `text()`: اختيار النص المناسب باللغة المطلوبة.
- `quick_replies()`: اقتراحات الرسائل السريعة للواجهة.
- `handoff()`: تجهيز تحويل واتساب بالرقم المحدد في الإعدادات، بدون إرفاق سجل المحادثة أو تفاصيل الطلب.

إذا لم يُضبط رقم واتساب، لا يتم اختراع رابط دعم.

**تعدّله عندما:** تريد تغيير أسلوب الكلام أو صياغة الردود أو أزرار الاقتراحات السريعة.

### `app/text.py` — أدوات مساعدة لمعالجة النصوص

- `digits()`: توحيد الأرقام العربية والفارسية إلى الشكل الإنجليزي للمقارنة.
- `normalize()`: توحيد بعض أشكال الحروف العربية وإزالة التشكيل والتطويل للمساعدة في البحث.
- `language_of()`: تحديد العربية أو الإنجليزية من الحروف، أو استخدام اللغة السابقة عند عدم وجود دليل واضح.
- `order_number_from_message()`: التحقق من وجود رقم الطلب المقترح فعلًا في رسالة العميل.
- `extract_number()`: استخراج رقم محتمل وفق القواعد الموجودة.
- `tokens()` و`score()`: تقسيم الكلمات وحساب تطابق بسيط تستخدمه التجربة المحلية.

**تعدّله عندما:** تحتاج دعم صيغة أخرى لأرقام الطلبات أو تحسين معالجة النص والبحث التجريبي. البحث المحلي هنا لا يستخدم embeddings أو قاعدة بيانات متجهات.

### `app/sessions.py` — ذاكرة المحادثة المؤقتة

يحفظ سياق كل عميل أثناء الجلسة ويمنع اختلاطه بجلسات الآخرين.

- `owner_key()`: ينشئ معرّف ملكية باستخدام هوية الجلسة وهوية العميل والمفتاح الداخلي.
- **`MemorySessions`:** يحفظ الجلسات في ذاكرة عملية Python، مناسب للتطوير المحلي بعملية واحدة.
- **`RedisSessions`:** يحفظها مؤقتًا في Redis لتتشارك عدة عمليات الخدمة نفس الجلسات وحدود الاستخدام.

يعالج انتهاء مدة الجلسة، وحذفها، وحدود الطلبات، ومنع معالجة رسالتين للجلسة نفسها في الوقت نفسه.

القيم الافتراضية تشمل انتهاء الجلسة بعد 1800 ثانية وحفظ آخر 8 أدوار محادثة. تغييرها متاح من الإعدادات. انتهاء جلسة المتصفح لا يصل تلقائيًا إلى Python؛ على Laravel إرسال طلب الحذف عند إنهائها، وتظل مهلة الانتهاء وسيلة لتنظيف الجلسات المتروكة.

**تعدّله عندما:** تريد تغيير طريقة التخزين أو قواعد الملكية والتزامن. مدة الاحتفاظ وحدود الاستخدام يمكن ضبطها من `.env`.

### `app/errors.py` — أنواع الأخطاء المعروفة

يعرّف استثناءات تستخدمها المكونات للتعبير عن المشكلة بشكل موحد:

| الاستثناء | معناه |
|---|---|
| `BackendUnavailable` | تعذر الحصول على بيانات صالحة من مصدر البيانات. |
| `OrderUnavailable` | الطلب غير متاح لهذا العميل، سواء لعدم وجوده أو لعدم ملكيته. |
| `PlannerUnavailable` | تعذر فهم الرسالة أو قبول نتيجة النموذج. |
| `SessionUnavailable` | الجلسة غير متاحة للعميل. |
| `Busy` | الخدمة أو الجلسة مشغولة حاليًا. |

**تعدّله عندما:** تضيف نوع فشل يحتاج معالجة خاصة في الخدمة أو الـAPI.

### `app/telemetry.py` — إعداد تسجيل أحداث التشغيل

يضبط سجلات التطبيق، ويقلل سجلات مكتبات HTTP وOpenAI التي قد تعرض تفاصيل غير مطلوبة. يستخدم التطبيق السجلات لمتابعة رقم الطلب، والعملية، والمدة، واستهلاك tokens دون تسجيل نص المحادثة في سجلاته التشغيلية المعتادة.

**تعدّله عندما:** تريد ربط نظام مراقبة أو تعديل مستوى السجلات. إعدادات سجلات خادم التشغيل والبنية المحيطة تُراجع بصورة مستقلة.

### `app/__init__.py` — تعريف حزمة التطبيق

ملف صغير يعرّف مجلد `app` كحزمة Python. لا يحتوي على منطق المحادثة، ولا يحتاج تعديلًا عادة.

### `app/data/catalog.json` — بيانات التجربة

يحتوي على 7 متاجر و14 منتجًا و3 أسئلة شائعة وطلبين تجريبيين، مع بيانات عربية وإنجليزية. يستخدمه `MockGateway` فقط.

مثال: الطلب `DEMO-1001` يخص العميل التجريبي `demo-customer`. الأسماء والسياسات والروابط هنا للتجربة، ويكون مصدر البيانات الحقيقي Laravel عند تفعيل الربط.

**تعدّله عندما:** تريد إضافة سيناريوهات محلية مثل منتج غير متوفر أو فئة منتجات مختلفة.

## 4. سكربتات التشغيل والمساعدة: مجلد scripts

| الملف | ماذا يفعل؟ | متى تستخدمه؟ |
|---|---|---|
| `scripts/demo.py` | يرسل محادثة تجريبية إلى خدمة تعمل بالفعل: تحية وترشيح وتتبع طلب، ثم يحذف الجلسة. | لتجربة الخدمة ومشاهدة الردود. يستخدم وضع الخدمة الحالي؛ إذا كانت تعمل بـOpenAI فقد تنتج عنه مكالمات مدفوعة. |
| `scripts/smoke.py` | يشغّل خادمًا محليًا مؤقتًا في وضع `demo/mock`، ويختبر طلبات HTTP فعلية ثم يغلقه. | للتأكد أن الأجزاء الأساسية تعمل معًا، بدون اتصال OpenAI أو Laravel. |
| `scripts/evaluate.py` | يختبر فهم OpenAI على 16 حالة عربية وإنجليزية، ويعرض النتائج والوقت وtokens. يتطلب `--live`. | بعد توفير مفتاح ونموذج لاختبار الفهم الحقيقي. يقيس مرحلة فهم الرسالة، وليس زمن الرد الكامل مع Laravel. |
| `scripts/export_openapi.py` | يولّد `docs/openapi.json` من تعريفات FastAPI باستخدام إعدادات تجريبية. | بعد تغيير عقد الـAPI لإرسال النسخة المحدثة للفريق. |
| `scripts/lock_dependencies.py` | يقرأ إصدارات المكتبات المثبتة وعلاقاتها ويكتب ملفات تثبيت الإصدارات. | بعد تحديث المكتبات عمدًا والتحقق منها. لا يحدّث المكتبات ولا يثبتها بنفسه. |

## 5. الاختبارات: مجلد tests

هذه الملفات تتحقق من سلوك الخدمة. لا تدخل في رحلة رسالة العميل أثناء التشغيل المعتاد.

| الملف | ماذا يختبر؟ |
|---|---|
| `tests/conftest.py` | يجهز الإعدادات وعميل الاختبار والـheaders المشتركة، مع عزل الاختبارات عن مفاتيح `.env` المحلية. |
| `tests/test_chat.py` | المحادثة باللغتين، الترشيح والميزانية، أسئلة المتابعة، الأسئلة الشائعة، شروط تتبع الطلب، عزل الجلسات، حدود الرسائل، والتحويل للدعم. |
| `tests/test_integrations.py` | شكل طلب OpenAI ونتيجته باستخدام اتصال وهمي، وعقد Laravel والتحقق من البيانات والملكية والروابط والإعدادات. |
| `tests/test_sessions.py` | تخزين الجلسات في الذاكرة وRedis التجريبي باستخدام fakeredis، والملكية والحذف والانتهاء والتزامن وحدود الاستخدام. |
| `tests/test_failures.py` | سلوك المهلات وانقطاع الاتصال والردود الكبيرة والتحقق من إعدادات الإنتاج. |

الاختبارات المحلية لا تتصل بخدمة OpenAI المدفوعة أو Laravel الحقيقي. اختبار الاتصال الحقيقي وجودة النموذج يحتاج الإعدادات النهائية.

## 6. مثال ربط Laravel

### `examples/LaravelAiController.php`

مثال لفريق الـbackend على استقبال رسالة الواجهة ثم إرسالها إلى خدمة Python.

- يتحقق من مدخلات العميل في Laravel.
- ينشئ هوية جلسة من جهة السيرفر، ويأخذ هوية العميل من تسجيل الدخول.
- يرسل المفتاح الداخلي والهوية في الـheaders.
- يحفظ معرّف جلسة المساعد للرسائل التالية.
- يتعامل مع تغيّر المستخدم وانتهاء جلسة المساعد وفشل الاتصال.
- يوفّر منطقًا لإنهاء جلسة المساعد وحذفها.

**دوره:** نقطة بداية يدمجها الفريق داخل مشروع Laravel مع الـroutes وإعدادات الخدمة والجلسات وCSRF وحدود الطلبات. الملف وحده لا ينشئ هذه الأجزاء داخل مشروعهم، ولم يُشغّل هنا داخل Laravel فعلي.

## 10. أعدّل فين لو عايز أعمل تغيير؟

| المطلوب | المكان الأساسي |
|---|---|
| إضافة مفتاح OpenAI واسم النموذج | `.env` ← `OPENAI_API_KEY`, `OPENAI_MODEL`, `PLANNER_MODE` |
| وضع عناوين endpoints التي سيجهزها Laravel | `.env` ← `BACKEND_BASE_URL` وحقول `BACKEND_*_PATH` والمفتاح والوضع |
| مطابقة أسماء حقول Laravel المختلفة | `app/gateway.py`، ومراجعة `app/models.py` وعقد البيانات |
| تغيير طريقة فهم طلب العميل | `app/planner.py` |
| تغيير صياغة الردود واللغة والأسلوب | `app/replies.py` |
| تغيير خطوات الترشيح وأسئلة المتابعة | `app/service.py`، وتعليمات القرار في `app/planner.py` عند الحاجة |
| تغيير عدد المنتجات المقترحة | `.env` ← `RECOMMENDATION_LIMIT` |
| تغيير مدة الجلسة وعدد أدوار السياق | `.env` ← `SESSION_TTL_SECONDS`, `HISTORY_TURNS` |
| إضافة رقم واتساب | `.env` ← `WHATSAPP_PHONE` |
| السماح بنطاقات روابط المنتجات والصور والتتبع | `.env` ← `ALLOWED_CATALOG_HOSTS`, `ALLOWED_TRACKING_HOSTS` |
| تغيير بيانات التجربة | `app/data/catalog.json` |
| تغيير شكل الرد الذي تستقبله الواجهة | `app/models.py` و`app/service.py`، ثم تحديث توثيق الـAPI |
| إضافة سلوك جديد | منطق التطبيق المناسب، ثم اختبار السيناريو في `tests/` |

### مثال: «عايز عطر تحت 200»

1. `main.py` يقبل الطلب بعد التحقق منه ويفتح سياق الجلسة عبر `sessions.py`.
2. `service.py` يستدعي `planner.py` لفهم الرسالة.
3. القرار يكون بحث منتجات عن عطر بحد أقصى 200.
4. `gateway.py` يطلب المنتجات من المصدر المحدد.
5. `service.py` يتحقق من النتائج ويجهز البطاقات والنص.
6. يرجع `ChatResponse` إلى Laravel لعرضه في الواجهة.

### مثال: «فين طلبي؟»

1. يُفهم أن المطلوب تتبع طلب.
2. لعدم وجود رقم طلب في الرسالة، يطلبه المساعد دون استدعاء endpoint الطلبات.
3. عندما يرسل العميل الرقم، يتحقق الكود من وجود هوية عميل مسجل.
4. يجلب `gateway.py` الطلب بهذه الهوية، ويتحقق Laravel من الملكية، ثم تتحقق الخدمة من المالك والرقم في الرد أيضًا.
5. يعرض `service.py` حالة الطلب المسموح بها. إذا كان الطلب غير موجود أو يخص شخصًا آخر، يرجع نفس رد عدم الإتاحة.

## 11. ترتيب مقترح لقراءة الكود

ابدأ بـ`README.md` للتشغيل، ثم اقرأ `models.py` لمعرفة أشكال البيانات، و`service.py` لفهم رحلة المحادثة. بعد ذلك اقرأ `planner.py` و`gateway.py`، ثم `main.py` و`sessions.py`. استخدم `tests/test_chat.py` لرؤية أمثلة عملية على السلوك المتوقع.

المرحلة المتبقية للربط الفعلي هي توفير مفتاح OpenAI والنموذج، واعتماد عقد البيانات مع Laravel، وتعبئة إعدادات الاتصال، ثم اختبار الجودة والوقت على الخدمات الحقيقية. قابلية ضبط المهلات لا تعني وحدها أن زمن الرد المستهدف تحقق.
