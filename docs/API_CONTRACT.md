# 📜 API Integration Contract (Laravel & Frontend)

**Version:** 1.0  
**Service Role:** Session-scoped bilingual conversational shopping assistant microservice.  
**Security Boundary:** The AI microservice resides on a private internal network behind Laravel. It does not connect directly to the database and performs **read-only** operations.

An auto-generated OpenAPI 3.1 specification is available in [`docs/openapi.json`](openapi.json). Regenerate it anytime via `python scripts/export_openapi.py`.

---

## 1. Laravel → AI Microservice

The Laravel backend acts as an authenticated proxy. The frontend browser never contacts the FastAPI service directly and never holds the `AI_SERVICE_TOKEN`.

### 1.1 POST `/v1/chat`

Processes a user message within an existing or newly initialized conversation session.

#### Required HTTP Headers
These headers must be constructed by Laravel and must never be accepted directly from frontend client headers:

| Header | Type | Description |
|---|---|---|
| `Authorization` | `string` | `Bearer <AI_SERVICE_TOKEN>` (Private service token). |
| `X-Session-Subject` | `string` | Opaque identifier generated by Laravel for the session (8–128 ASCII alphanumeric / `_` / `-` characters). Bound to the session state. |
| `X-Customer-ID` | `string` (Optional) | Authenticated customer identifier. Omitted for guest visitors. |
| `Content-Type` | `string` | `application/json` |

> [!IMPORTANT]
> If a user logs in, logs out, or changes accounts, Laravel must issue a fresh `X-Session-Subject` or terminate the old session. A session is strictly bound to both the subject and the customer ID.

#### Request Body Schema
```json
{
  "message": "I need a perfume under 200 SAR",
  "session_id": null,
  "locale": "en",
  "current_store_id": "store-1"
}
```

* `message` (*string*, required): 1 to 300 characters after whitespace trimming.
* `session_id` (*string \| null*, optional): `null` to initiate a new session; subsequent calls pass the UUID returned by the preceding response.
* `locale` (*string*, optional): Preferred fallback language (`"ar"` or `"en"`, default `"ar"`). The microservice automatically detects explicit language from the user's message.
* `current_store_id` (*string \| null*, optional): Optional UI store context. Note that the assistant searches across all platform stores unless explicitly instructed.
* *Note:* User IDs and client-supplied conversation history are not accepted in the JSON body.

#### Response Body Schema (HTTP 200 OK)
```json
{
  "request_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "session_id": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "language": "en",
  "answer": "Here are curated recommendations from our stores that match your budget:",
  "product_cards": [
    {
      "id": "product-1",
      "store_id": "store-1",
      "name": "Luxury Amber Perfume",
      "description": "Rich amber and floral notes for evening wear.",
      "price": "150.00",
      "original_price": "180.00",
      "currency": "SAR",
      "url": "https://shop.example/products/1",
      "image_url": "https://cdn.example/images/product-1.jpg",
      "updated_at": "2026-10-07T09:00:00Z"
    }
  ],
  "store_cards": [],
  "order": null,
  "faq_ids": [],
  "quick_replies": [
    "Find a gift",
    "Browse stores",
    "Shipping & Delivery",
    "Track my order"
  ],
  "handoff": {
    "requested": false,
    "url": null
  },
  "requires_login": false,
  "requires_order_number": false,
  "demo": false,
  "degraded": false,
  "elapsed_ms": 482
}
```

#### Field Specifications:
* `price` & `original_price`: Formatted as strings to preserve currency decimal precision.
* `order`: Populated only when the customer has provided their order number, is authenticated, and order ownership is verified by the backend.
* `requires_login`: Indicates the customer inquired about an order but is browsing as a guest.
* `requires_order_number`: Indicates the customer requested order status without providing their order reference.
* `handoff`: Contains WhatsApp support deep-link if human escalation is triggered.
* `degraded`: Indicates a non-critical backend timeout occurred and safe fallback answers were provided.

### 1.2 DELETE `/v1/sessions/{session_id}`

Terminates an active session and expunges its conversation context from the session store.

* **Headers**: Same authentication headers as `/v1/chat`.
* **Response**: `204 No Content`.
* **Usage**: Laravel should invoke this when the user clicks "End Chat" or logs out. Inactive sessions are automatically evicted after the configured sliding TTL (default: 30 minutes).

---

### 1.3 HTTP Error Codes

| Status Code | Reason | Expected Client / Laravel Action |
|---|---|---|
| `400 Bad Request` | Invalid session subject or malformed header. | Verify header values generated by Laravel. |
| `401 Unauthorized` | Missing or invalid `AI_SERVICE_TOKEN`. | Check configuration in `services.php` / `.env`. |
| `404 Not Found` | Session not found or expired. | Reset `session_id` to `null` and retry message in a new session. |
| `409 Conflict` | Concurrent message on active session, or session store limit reached. | Respect `Retry-After` header. |
| `413 / 422 Unprocessable` | Input validation failure (e.g. message > 300 characters). | Validate user input before submission. |
| `429 Too Many Requests` | Rate limit exceeded. | Throttle client requests according to `Retry-After`. |
| `503 Service Unavailable` | Redis unavailable or downstream degraded. | Display friendly temporary service unavailable message. |

## 2. AI Microservice → Laravel (Upstream Read Endpoints)

When running in `BACKEND_MODE=laravel`, the microservice queries these 4 read-only HTTP endpoints.  
Every request includes:
```http
Authorization: Bearer <BACKEND_API_TOKEN>
Accept: application/json
```

### 2.1 GET `/api/ai/stores`
Fetches active platform stores.
* **Query Parameters**: `query` (optional string), `active=1`
* **Response**:
```json
{
  "data": [
    {
      "id": "store-1",
      "name_ar": "متجر لولو للعطور",
      "name_en": "Loulou Perfumes",
      "description_ar": "عطور شرقية وفاخرة",
      "description_en": "Luxury oriental fragrances",
      "url": "https://shop.example/stores/perfumes",
      "active": true
    }
  ]
}
```

### 2.4 GET `/api/ai/orders/{order_number}`
Retrieves customer-owned order status.
* **Headers**: `X-Customer-ID: <authenticated-customer-id>`
* **Security Constraints**:
  - The endpoint is **never invoked** unless the customer provided an explicit order number in their message AND is authenticated.
  - The query on Laravel MUST filter by both `order_number` AND `customer_id`.
  - If the order belongs to another customer, Laravel must return `404 Not Found` (never disclose order existence to unauthorized callers).
* **Response**:
```json
{
  "data": {
    "order_number": "ORDER-1001",
    "customer_id": "123",
    "status": "shipped",
    "tracking_url": "https://carrier.example/track/1001",
    "updated_at": "2026-10-07T09:00:00Z"
  }
}
```
* **Supported Order Status Values**: `processing`, `synced`, `shipped`, `delivered`, `cancelled`, `sync_error`, `refund_pending`, `refunded`.
